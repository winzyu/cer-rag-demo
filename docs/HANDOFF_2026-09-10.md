## 5. Findings and defects opened this session

Every one verified in code, none fixed.

**Report event pipeline:**

1. **`detectAlgalBloom` bypasses the confidence-floor downgrade.** Every other event type below
   `CONFIDENCE_FLOOR` (0.5) is rewritten to `Inconclusive`; the bloom detector returns
   `"Algal bloom"` at confidence 0.45 directly, with severity hardcoded `"Moderate"`.
2. **Two event types are unreachable.** `Industrial` is classified at 0.3 and `Saltwater intrusion`
   at 0.45, both below the floor, so both are always rewritten to `Inconclusive`. No `WQEvent` can
   ever carry either type.
3. **No diel/tidal classifier exists.** `buildReportInput.ts` tags every live parameter
   `pattern: "unknown"`. This disables `detectAlgalBloom` entirely on live data (it requires a
   `diel` tag) *and* disables the skip that stops a normal daily swing from opening an event window
   at every baseline crossing. One missing component, two opposite failure modes.
4. **No `Pattern` value for a slow multi-week trend** — which is what drought-driven salinity creep
   looks like. Such a case matches neither the diel/tidal exclusion nor the persistent-offset rule.

**Turbidity — operator answers received 2026-09-10, not yet acted on:**

5. **Our clarity bands disagree with the operator's.** The conversion is confirmed as
   `NTU = (3.35 − V) × 300`, which matches what `referenceRanges.ts` reverse-engineered. But the
   operator defines **three** bands — Clear below 2.2 V (≈345), Moderate 0.7–2.2 V (≈345–795),
   Turbid below 0.7 V (≈>795) — against our four provisional edges at 250 / 600 / 1005. Adopt his.
   Recommend keeping ≥1005 as an **off-scale data-quality flag** rather than a band: it means the
   input went below 0 V, and one recorded pod mean sits at 1006.
6. **The system prompt's turbidity range is wrong on the live scale.** It declares 0–25 NTU
   freshwater / 0–10 saltwater; recorded production readings run 0–1,689 (48 samples, median 0). The
   report layer already sidesteps this by treating turbidity as a relative index with a caveat; chat
   does not, so every non-zero reading reads as a massive exceedance. **Open question for the
   operator: is 0–25 NTU the Turner's range?** That would explain the discrepancy entirely.
7. **Two turbidity sensors, and the software cannot tell them apart.** Turner (quantitative
   reliable) and Keystudio (qualitative only). The operator says the software will know which, but
   it is not built. Until a per-device sensor-model field exists beside `operatingEnvironment`, the
   only safe chat rule is qualitative-only for all pods.
8. **Clean Earth Rovers referral scope, confirmed:** algal bloom cleanup, fish kill cleanup, debris
   capture, oil spill response; everything else referred elsewhere. Note the irony to design around
   — of those four, only algal bloom maps to a detectable event, and that detector cannot fire on
   live data (defect 3).

**Audit log:**

9. **The lookup path needs a Firestore composite index.** `findAuditLogRecords` combines a `caller`
   equality filter with a `timestamp` range and an `orderBy`; there is no `firestore.indexes.json`
   in the repo, so the first real query throws `FAILED_PRECONDITION`.
10. **No retention policy.** Records hold the question, the full answer (which can contain customer
    sensor readings — `SPECS.md` §18 treats those as confidential) and a caller identity that is a
    token hash or an IP. Settle retention and access before the flag is switched on.

**Eval set:**

11. **Slice-coverage overshoot.** Wave-1 exit criterion 3 wanted ≥25% of turns answerable only
    outside the ◆G9 slice; the set delivers **88%** (37 of 42 answerable fixtures draw entirely on
    non-slice documents, 74 of 84 answerable turns). The criterion passes, but the set barely tests
    where direct-feed is strong, so Phase 4 conclusions must be read as "on questions requiring the
    manuals", not "in general". Settle before wave 2 spends its budget.
12. **`refusal-turbidity-sensor-hardware` may now be wrong.** Its rubric demands the assistant state
    that the corpus cannot identify the turbidity instrument. Still literally true of the corpus —
    but the operator has now named Turner and Keystudio, and the moment that reaches the prompt the
    fixture demands a refusal for something answerable.
13. **Label type drift.** Every `RelevantChunk` on disk carries `locator` and `claimIds`, neither
    declared in `src/eval/retrieval/types.ts`. Add `locator` to the type rather than stripping it —
    it is the handle that lets a label survive a future re-chunk.

## 6. The source-of-truth document — recommended: do not cut the ranges yet

The operator proposed removing the range tables from `water-quality-metrics-source-of-truth.pdf` and
keeping the parameter reference, correlation matrix and interrelated-parameter behaviour.

**All four `precedence` fixtures depend on that document**, and the precedence class exists to test
exactly the conflict the removal would eliminate — operator range versus document range, operator
wins. Removing the ranges costs 8 of 92 turns their premise. Four label files point into the
document, and it is only 5 chunks, so a table removal plausibly invalidates one to three of them.

The ranges sitting in the document are not a defect. They are what proves the precedence rule works.

Recommendation: keep the document unchanged through the generation baseline, then revisit as a
deliberate, re-labelled corpus change. The operator asked for a "what to remove" list rather than
the edit itself — that list can be produced without touching the file, and should be, since it costs
nothing and blocks nothing.
